= Concrete Task Types Reference

[abstract]
--
Complete reference for all built-in task types provided by TaskGraph. This chapter documents every concrete task implementation, its DSL features, configuration options, and usage examples.
--

[NOTE]
====
*FULLY IMPLEMENTED* — All concrete task types listed in this chapter exist as classes and are registered in `TaskType`. Every type has a dedicated DSL convenience method in `TaskGraphDsl` as well as being accessible via `task(id, TaskType.XXX) { ... }`.

DSL convenience methods available inside `TaskGraph.build {}`: +
`task()` / `serviceTask()` • `httpTask()` • `scriptTask()` • `sqlTask()` • `noSqlTask()` • `messagingTask()` • `fileTask()` • `dataTransform()` • `timer()` • `businessRule()` • `loop()` • `callActivity()` • `saga()` • `parallel()` / `parallelGateway()` • `fork()` • `join()`

Note: Kafka is accessed via `messagingTask()` with a Kafka provider; S3/cloud storage via `ObjectStoreTask` directly.
====


== Overview

TaskGraph provides 15+ concrete task types organized by category:

* **Core Tasks** - ServiceTask, ScriptTask
* **HTTP/REST** - HttpTask, RestTask, GraphQLTask
* **Database** - SqlTask, NoSqlTask, BatchSqlTask
* **File Operations** - FileTask, CsvTask, JsonTask, XmlTask
* **Messaging** - MessagingTask, KafkaTask, RabbitMQTask
* **Cloud Services** - S3Task, BlobStorageTask, LambdaTask
* **Utilities** - DelayTask, LogTask, TransformTask

== Core Tasks

=== ServiceTask

Generic task for executing arbitrary code.

[source,groovy]
----
task("service-task") {
    action { ctx ->
        // Any custom logic
        def input = ctx.prev
        def result = processData(input)
        return result
    }

    // With method reference
    action this::myMethod

    // With closure delegate
    action { ctx ->
        def userId = ctx.global("userId")
        return userService.getUser(userId)
    }
}

// Configuration
task("configured-service") {
    description "Process user data"
    timeout 30000
    retryPolicy {
        maxAttempts 3
        delay 1000
    }

    action { ctx ->
        performWork()
    }
}
----

=== ScriptTask

Execute Groovy scripts with sandboxing.

[source,groovy]
----
scriptTask("groovy-script") {
    language "groovy"  // Default
    sandboxed true     // Default

    script '''
        def data = bindings.data
        def result = data.collect { it * 2 }
        return result
    '''

    bindings([
        data: [1, 2, 3, 4, 5]
    ])

    // Dynamic bindings
    bindings { ctx ->
        [
            userId: ctx.global("userId"),
            data: ctx.prev
        ]
    }
}

// Custom script base class
scriptTask("custom-base") {
    customScriptBaseClass CompanyScriptBase

    script '''
        // Company-specific methods available
        def data = queryDataWarehouse("SELECT * FROM sales")
        return processData(data)
    '''
}

// JavaScript (via GraalVM)
scriptTask("javascript") {
    language "javascript"

    script '''
        const data = bindings.data;
        const result = data.map(x => x * 2);
        return result;
    '''
}
----

== HTTP/REST Tasks

=== HttpTask

Make HTTP requests.

[source,groovy]
----
httpTask("api-call") {
    url "https://api.example.com/users"
    method GET

    // Headers
    header "Authorization", "Bearer ${credential('api-token')}"
    header "Content-Type", "application/json"
    header "User-Agent", "TaskGraph/2.0"

    headers {
        "X-Request-ID": UUID.randomUUID().toString()
        "X-Correlation-ID": ctx.global("correlationId")
    }

    // Query parameters
    queryParam "page", "1"
    queryParam "limit", "100"

    queryParams([
        page: 1,
        limit: 100,
        sort: "name"
    ])

    // Timeout
    timeout 30000
    connectTimeout 5000
    readTimeout 10000

    // Retry
    retryPolicy {
        maxAttempts 3
        retryOn(IOException, SocketTimeoutException)
    }

    // SSL
    validateSSL true
    trustStore "/path/to/truststore.jks"

    // Response handling
    responseHandler { response ->
        if (response.statusCode == 200) {
            return response.body
        } else {
            throw new ApiException("API returned ${response.statusCode}")
        }
    }
}

// POST with JSON body
httpTask("post-json") {
    url "https://api.example.com/users"
    method POST

    json {
        name: "Alice"
        email: "alice@example.com"
        age: 30
    }

    // Or from variable
    json { ctx -> ctx.prev }
}

// Form data
httpTask("form-post") {
    url "https://api.example.com/submit"
    method POST
    contentType "application/x-www-form-urlencoded"

    formData {
        username: "alice"
        password: credential("user-password")
    }
}

// Multipart upload
httpTask("file-upload") {
    url "https://api.example.com/upload"
    method POST
    contentType "multipart/form-data"

    multipart {
        file "document", new File("/path/to/file.pdf")
        field "description", "Important document"
    }
}
----

=== RestTask

Higher-level REST API client.

[source,groovy]
----
restTask("rest-api") {
    baseUrl "https://api.example.com"
    version "v1"  // Added to path: /v1/

    // Authentication
    auth {
        bearer credential("api-token")
        // or: basic username: "user", password: credential("password")
        // or: oauth2 clientId: "...", clientSecret: credential("...")
    }

    // GET request
    get("/users/${userId}")

    // POST with auto-serialization
    post("/users") {
        body([
            name: "Alice",
            email: "alice@example.com"
        ])
    }

    // PUT
    put("/users/${userId}") {
        body(updatedUser)
    }

    // DELETE
    delete("/users/${userId}")

    // Response deserialization
    responseType User.class

    // Error handling
    errorHandler {
        on(404) { response ->
            log.warn("User not found")
            return null
        }

        on(500..599) { response ->
            throw new ServerException("Server error: ${response.body}")
        }
    }
}
----

=== GraphQLTask

Execute GraphQL queries.

[source,groovy]
----
graphqlTask("query-users") {
    endpoint "https://api.example.com/graphql"

    query '''
        query GetUsers($limit: Int!) {
            users(limit: $limit) {
                id
                name
                email
                orders {
                    id
                    total
                }
            }
        }
    '''

    variables {
        limit: 10
    }

    // Authentication
    header "Authorization", "Bearer ${credential('graphql-token')}"

    // Response extraction
    extractPath "data.users"

    // Error handling
    onGraphQLError { errors ->
        errors.each { error ->
            log.error("GraphQL error: ${error.message}")
        }
        throw new GraphQLException("Query failed")
    }
}

// Mutation
graphqlTask("create-user") {
    endpoint "https://api.example.com/graphql"

    mutation '''
        mutation CreateUser($input: CreateUserInput!) {
            createUser(input: $input) {
                id
                name
                email
            }
        }
    '''

    variables { ctx ->
        def user = ctx.prev
        [input: [
            name: user.name,
            email: user.email
        ]]
    }
}
----

== Database Tasks

=== SqlTask

Execute SQL queries.

[source,groovy]
----
sqlTask("query-users") {
    datasource myDataSource

    query """
        SELECT id, name, email, created
        FROM users
        WHERE status = ?
          AND created > ?
        ORDER BY created DESC
        LIMIT ?
    """

    parameters(["active", yesterday, 100])

    // Dynamic parameters
    parameters { ctx ->
        [
            ctx.global("status"),
            ctx.global("since"),
            ctx.global("limit")
        ]
    }

    // Row mapping
    rowMapper { rs ->
        [
            id: rs.getLong("id"),
            name: rs.getString("name"),
            email: rs.getString("email"),
            created: rs.getTimestamp("created")
        ]
    }

    // Or map to class
    rowMapper User.class

    // Result processing
    resultProcessor { rows ->
        return rows.collect { enrichUser(it) }
    }
}

// INSERT/UPDATE/DELETE
sqlTask("update-user") {
    datasource myDataSource

    query """
        UPDATE users
        SET name = ?, email = ?, updated = NOW()
        WHERE id = ?
    """

    parameters { ctx ->
        def user = ctx.prev
        [user.name, user.email, user.id]
    }

    // Check affected rows
    validateRowCount { rowCount ->
        if (rowCount == 0) {
            throw new NotFoundException("User not found")
        }
    }
}

// Transactions
sqlTask("transactional") {
    datasource myDataSource
    transactional true
    isolationLevel SERIALIZABLE

    action { ctx ->
        // Multiple queries in transaction
        executeUpdate("UPDATE accounts SET balance = balance - ? WHERE id = ?", [100, fromId])
        executeUpdate("UPDATE accounts SET balance = balance + ? WHERE id = ?", [100, toId])

        return "Transfer complete"
    }

    onError { error ->
        // Transaction automatically rolled back
        log.error("Transaction failed, rolled back", error)
    }
}
----

=== BatchSqlTask

Batch database operations for performance.

[source,groovy]
----
batchSqlTask("batch-insert") {
    datasource myDataSource

    query """
        INSERT INTO users (name, email, created)
        VALUES (?, ?, NOW())
    """

    // Batch data
    batchParameters { ctx ->
        def users = ctx.prev

        users.collect { user ->
            [user.name, user.email]
        }
    }

    batchSize 1000  // Insert 1000 at a time

    onBatchComplete { batchNum, rowsAffected ->
        log.info("Batch ${batchNum} completed: ${rowsAffected} rows")
    }
}
----

=== NoSqlTask

Access NoSQL databases.

[source,groovy]
----
// MongoDB
noSqlTask("mongo-query") {
    provider "mongodb"
    database "mydb"
    collection "users"

    // Find documents
    find {
        status: "active"
        age: [$gt: 18]
    }

    projection {
        _id: 1
        name: 1
        email: 1
    }

    sort { created: -1 }
    limit 100

    // Result mapping
    resultType User.class
}

// MongoDB insert
noSqlTask("mongo-insert") {
    provider "mongodb"
    database "mydb"
    collection "users"

    insert { ctx ->
        ctx.prev.collect { user ->
            [
                name: user.name,
                email: user.email,
                created: new Date()
            ]
        }
    }
}

// Redis
noSqlTask("redis-cache") {
    provider "redis"

    operation SET
    key { ctx -> "user:${ctx.global('userId')}" }
    value { ctx -> JsonOutput.toJson(ctx.prev) }
    ttl 3600  // 1 hour

    // Or GET
    // operation GET
    // key { ctx -> "user:${ctx.global('userId')}" }
}

// Elasticsearch
noSqlTask("elasticsearch") {
    provider "elasticsearch"
    index "users"

    query {
        bool: {
            must: [
                [match: [status: "active"]],
                [range: [age: [gte: 18]]]
            ]
        }
    }

    size 100
    sort [[created: "desc"]]
}

== File Operation Tasks

=== FileTask

Read, write, copy, move files.

[source,groovy]
----
// Read file
fileTask("read-file") {
    operation READ
    sources(["/data/input/file.txt"])

    securityConfig {
        allowedDirectories(["/data/input"])
        maxFileSize 10 * 1024 * 1024  // 10 MB
    }

    encoding "UTF-8"

    // Process content
    contentProcessor { content ->
        return content.toUpperCase()
    }
}

// Write file
fileTask("write-file") {
    operation WRITE
    destination "/data/output/result.txt"

    content { ctx ->
        JsonOutput.prettyPrint(JsonOutput.toJson(ctx.prev))
    }

    securityConfig {
        allowedDirectories(["/data/output"])
    }

    overwrite true
    createDirectories true
}

// Copy files
fileTask("copy-files") {
    operation COPY
    sources(["/data/input/*.txt"])
    destination "/data/archive/"

    preserveTimestamp true
    overwriteExisting false
}

// Move files
fileTask("move-files") {
    operation MOVE
    sources(["/data/temp/*.dat"])
    destination "/data/processed/"

    atomicMove true
}

// Delete files
fileTask("cleanup") {
    operation DELETE
    sources(["/data/temp/*"])

    securityConfig {
        allowedDirectories(["/data/temp"])
    }
}

=== CsvTask

Read and write CSV files.

[source,groovy]
----
// Read CSV
csvTask("read-csv") {
    operation READ
    source "/data/customers.csv"

    headers true  // First row is headers
    delimiter ","
    quote '"'

    // Map to objects
    rowMapper { row ->
        [
            id: row[0] as Long,
            name: row[1],
            email: row[2]
        ]
    }

    // Or with named columns
    rowMapper { columns ->
        [
            id: columns['id'] as Long,
            name: columns['name'],
            email: columns['email']
        ]
    }
}

// Write CSV
csvTask("write-csv") {
    operation WRITE
    destination "/data/output/results.csv"

    headers(["ID", "Name", "Email"])

    data { ctx ->
        ctx.prev.collect { user ->
            [user.id, user.name, user.email]
        }
    }

    delimiter ","
    includeHeaders true
}

=== KafkaTask

Apache Kafka operations.

[source,groovy]
----
// Produce to Kafka
kafkaTask("produce") {
    operation PRODUCE

    topic "user-events"
    key { ctx -> ctx.global("userId") }

    message { ctx ->
        [
            event: "USER_CREATED",
            userId: ctx.global("userId"),
            data: ctx.prev,
            timestamp: System.currentTimeMillis()
        ]
    }

    partition 0  // Optional
    headers {
        "event-type": "user.created"
    }

    // Delivery semantics
    acks "all"
    retries 3

// Consume from Kafka
kafkaTask("consume") {
    operation CONSUME

    topics(["user-events", "order-events"])
    groupId "taskgraph-consumer"

    pollDuration 1000  // 1 second
    maxRecords 100

    recordHandler { record ->
        log.info("Consumed: ${record.topic()}-${record.partition()}-${record.offset()}")
        processRecord(record.value())
    }

    commitSync true
}

== Task Configuration Patterns

=== Combining Features

[source,groovy]
----
httpTask("comprehensive") {
    // Identity
    name "Fetch User Data"
    description "Fetches user data from API"

    // HTTP config
    url "https://api.example.com/users/${userId}"
    method GET
    header "Authorization", "Bearer ${credential('api-token')}"

    // Resilience
    timeout 30000
    retryPolicy {
        maxAttempts 3
        delay 1000
        exponentialBackoff true
        retryOn(IOException, TimeoutException)
    }
    circuitBreaker {
        failureThreshold 5
        timeout 30000
    }

    // Concurrency
    concurrencyLimit 10
    resource "api-rate-limit", max: 100

    // Idempotency
    idempotencyPolicy {
        enabled true
        ttl 3600
        keyExtractor { ctx -> "fetch-user-${userId}" }
    }

    // Events
    beforeExecute {
        log.info("Fetching user ${userId}")
        startTimer()
    }

    afterExecute { result ->
        log.info("Fetched user: ${result.name}")
        stopTimer()
    }

    onError { error ->
        log.error("Failed to fetch user", error)
        alertOps(error)
    }

    // Validation
    responseHandler { response ->
        if (response.statusCode == 200) {
            return JsonSlurper().parseText(response.body)
        } else if (response.statusCode == 404) {
            return null  // User not found
        } else {
            throw new ApiException("API error: ${response.statusCode}")
        }
    }
}

== Intelligent / Agentic Task Types

[NOTE]
====
The intelligent task types documented in this section are _library-level abstractions_ defined in GroovyConcurrentUtils. They are designed to be wired and executed by the `mcp-agentic-workflow` server, which supplies the LLM provider, `WorkingMemory`, and event bus at runtime via its `FlowTypeRegistry`. You do not instantiate these task types directly via the standard `TaskGraph.build {}` DSL — they are used through flow descriptors and the `FlowTypeRegistry.register()` factory pattern.
====

=== LlmTask

`LlmTask` is a `ServiceTask` subclass representing a single-shot LLM inference call within a `TaskGraph` flow. It decouples prompt configuration from the actual LLM provider by accepting a `llmCallFn` closure injected at wiring time by `FlowTypeRegistry`.

==== Fields

[cols="2,1,4", options="header"]
|===
| Field | Type | Description
| `systemPrompt` | `String` | System prompt sent to the LLM. Sets role and behavioural constraints.
| `userPromptTemplate` | `String` | User prompt, optionally containing `${prev}` and `${nodeId.field}` template tokens resolved from `WorkingMemory`.
| `modelTier` | `String` | Routing hint: `SIMPLE`, `MODERATE`, `COMPLEX`, or `CRITICAL`. Used by `RoutingEngine` to select provider.
| `temperature` | `float` | Sampling temperature (default `0.3`). Lower = more deterministic.
| `maxParseRetries` | `int` | Number of corrective retry attempts if `outputSchema` JSON parse fails (default `1`).
| `outputSchema` | `Map` | Optional. If set, raw LLM output is stripped of markdown fences and parsed as JSON via `JsonSlurper`. One corrective retry is attempted on failure.
| `llmCallFn` | `Closure` | Injected by `FlowTypeRegistry`. Signature: `(String sysPrompt, String userPrompt, String modelTier, float temperature) -> String`. Routes to `RoutingEngine` (embedded provider) or HTTP orchestrator fallback.
|===

==== Prompt Template Resolution

The `userPromptTemplate` field supports `${expression}` tokens resolved from `WorkingMemory` at execution time:

[cols="2,3", options="header"]
|===
| Token | Resolves to
| `${prev}` | Result of the immediately upstream node
| `${nodeId.field}` | Field `field` from the result map of node `nodeId` in `WorkingMemory.resultsByNode`
| `${factName}` | Value from `WorkingMemory.sharedFacts`
|===

==== outputSchema and JSON mode

When `outputSchema` is set, the task enters structured-output mode:

. Raw LLM response is stripped of markdown code fences (` ```json ` ... ` ``` `)
. `JsonSlurper.parseText()` is called on the stripped content
. On `JsonException`: a corrective prompt is sent including the parse error, the expected schema, and the failed response. The corrected response is parsed once more.
. If parsing still fails, the exception propagates and the node is marked `TASK_FAILED`

[IMPORTANT]
====
Do **not** rely on the LLM echoing your input data as its JSON output. Write an explicit `systemPrompt` instructing the model to generate its own structured assessment. Models like Qwen3 with thinking mode can burn their token budget on `<think>` blocks and output only a minimal stub if the prompt is ambiguous.
====

==== Streaming mode

When `p.stream = true` is set in the flow node params AND a `RoutingEngine` is available, the task calls `provider.streamComplete()` instead of `provider.complete()`. Each chunk is:

* Appended to a `StringBuilder`
* Emitted as a `TEXT_MESSAGE_CONTENT` event via `PipelineEventBus` (AG-UI protocol alignment)
* Written to `ctx.globals['__text_message_content__']` for downstream inspection

OllamaProvider implements real NDJSON streaming (`/api/generate stream:true`). AnthropicProvider implements real SSE streaming (`content_block_delta` events). LMStudioProvider uses a safe blocking fallback.

==== Example (flow descriptor node)

[source,json]
----
{
  "id": "analyse-build",
  "taskType": "llm.inference",
  "dependsOn": ["run-build"],
  "params": {
    "systemPrompt": "You are a build health analyst. Assess the build result and respond with a JSON object.",
    "userPromptTemplate": "Build output: ${run-build.output}. Issues: ${run-build.issueCount}.",
    "modelTier": "MODERATE",
    "temperature": 0.2,
    "outputSchema": {
      "healthy": "boolean",
      "confidence": "float",
      "summary": "string"
    }
  }
}
----

=== ControlTask (control.policy)

`ControlTask` represents a policy gate in a flow graph. It evaluates a list of Groovy rule expressions against the upstream node result and returns a `ControlAction` that can drive conditional graph routing.

The `control.policy` task type is registered in `FlowTypeRegistry` and delegates evaluation to `PolicyEvaluator`.

==== ControlAction

`ControlAction` is the return type of a `control.policy` node. It carries:

[cols="2,4", options="header"]
|===
| Field | Description
| `action` | One of: `CONTINUE`, `ABORT`, `ESCALATE`, `ROUTE`
| `target` | (Optional) Node ID to route to when `action=ROUTE`
| `reason` | Human-readable explanation of which rule fired
| `metadata` | Arbitrary Map of additional context from the rule
|===

==== Rule structure

Each rule in `policy.rules` is a map with:

[cols="2,1,4", options="header"]
|===
| Key | Required | Description
| `when` | ✅ | Groovy expression string. Evaluated with bindings: `input` (upstream result), `globals` (ctx.globals), `memory` (WorkingMemory snapshot)
| `action` | ✅ | `CONTINUE` \| `ABORT` \| `ESCALATE` \| `ROUTE`
| `target` | ❌ | Target node ID (only meaningful for `ROUTE`)
| `reason` | ❌ | Human-readable label for logging and events
|===

Rules are evaluated in order. The first matching rule wins. If no rule matches, `policy.default` fires.

[IMPORTANT]
====
Use `input.fieldName` (not `prev.fieldName`) in rule `when` expressions. The `input` binding is populated from the result of `inputNodeId` (or `prev` if not specified). `prev` in the closure context is the raw upstream value — `input` is the resolved, policy-visible value.
====

==== Example (flow descriptor node)

[source,json]
----
{
  "id": "gate-build",
  "taskType": "control.policy",
  "dependsOn": ["analyse-build"],
  "params": {
    "inputNodeId": "analyse-build",
    "policy": {
      "rules": [
        {
          "when": "input.healthy == true && input.confidence >= 0.8",
          "action": "CONTINUE",
          "reason": "Build healthy with high confidence"
        },
        {
          "when": "input.healthy == false",
          "action": "ABORT",
          "reason": "Build reported unhealthy"
        },
        {
          "when": "input.confidence < 0.6",
          "action": "ESCALATE",
          "reason": "Low confidence - needs human review"
        }
      ],
      "default": {
        "action": "CONTINUE",
        "reason": "No rule matched - defaulting to continue"
      }
    }
  }
}
----

=== ManualTask (library: implemented; FlowTypeRegistry factory: planned)

`ManualTask` is a fully implemented task type in GroovyConcurrentUtils that pauses graph execution
until an external caller explicitly completes it. It is the library-level implementation of the
human-in-the-loop pattern.

==== What is already implemented

`ManualTask` (in `org.softwood.dag.task`) provides:

* Three completion outcomes: `SUCCESS`, `FAILURE`, `SKIP`
* Form field support (`form { field 'approved', type: FieldType.BOOLEAN, required: true }`)
* Assignee / role-based assignment
* Priority levels (`LOW`, `NORMAL`, `HIGH`, `URGENT`)
* Due dates with configurable timeout and `autoAction` on expiry
* Notification channels: email, Slack, webhook (`notify { email ...; slack ... }`)
* Escalation rules: automated reassignment after duration (`escalate { after 24.hours, to: '...' }`)
* Completion handlers: `onSuccess`, `onFailure`, `onSkip`

A `ManualTaskContext` carries the completed form data, attachments, outcome, completedBy, and
timestamp to the handlers.

==== What is planned: FlowTypeRegistry factory

What is _not yet_ implemented is the `human.input` task type factory in `FlowTypeRegistry`
(the `mcp-agentic-workflow` server). This factory would:

. Create a `ManualTask` instance and register it in the graph
. Emit an `INTERRUPT` event via `PipelineEventBus` with a `resumeToken` and prompt
. Expose completion via `flow_management action=resume runId=<id> input={...}` which calls
  `manualTask.complete(outcome: ..., formData: ..., completedBy: ...)`
. Resume downstream node scheduling once the promise resolves

This maps to the AG-UI `INTERRUPT` → resume handshake and enables human-in-the-loop validation
gates within otherwise automated flows.

==== Semantic equivalent today

Until the `human.input` factory is implemented, use `control.policy` with `action=ESCALATE`
to signal that human review is needed. The ESCALATE action surfaces in flow events and can be
handled by the consuming MCP client (e.g. Claude Desktop) to prompt the user.

=== EffectClass annotation (planned)

`@EffectClass` is a planned annotation for task types that produce side effects (file writes, HTTP mutations, database writes, LLM API calls). When applied, the TaskGraph execution engine can:

* Log the effect type in `WorkingMemory` alongside the node result
* Enable dry-run mode (skip side-effect nodes, return mocked results)
* Surface effect provenance in flow events for audit trail

This is not yet implemented but is part of the intelligent flow roadmap.

== WorkingMemory

`WorkingMemory` is the shared state carrier for intelligent flow runs. It is created per `TaskGraph` execution and threaded through all nodes via `ctx.globals['__workingMemory']`.

=== Structure

[cols="2,2,4", options="header"]
|===
| Field | Type | Description
| `runId` | `String` | UUID stamped by `FlowExecutionService` after `start()`. Correlates with all flow events.
| `resultsByNode` | `Map<String, Object>` | Append-only. Keyed by node ID. Written by `FlowBuilder.wrappedAction` on each node completion via `TaskResult`.
| `sharedFacts` | `Map<String, Object>` | Mutable shared scratch space. Tasks can read/write arbitrary key-value pairs here.
| `globals` | `Map<String, Object>` | Mirror of `ctx.globals` at snapshot time. Includes `__llm_provenance__`, `__llm_inputs_hash__`, `__text_message_content__`.
|===

=== Thread safety

`resultsByNode` writes are guarded by `synchronized(this)`. `sharedFacts` is a `ConcurrentHashMap`. The `toSnapshot()` method returns a deep-copy Map safe for prompt template resolution without holding locks.

=== Integration with LlmTask

`FlowTypeRegistry` resolves `userPromptTemplate` tokens using `WorkingMemory.toSnapshot()` before calling `llmCallFn`. This means any upstream node result is available for interpolation by name, without the downstream node needing a direct reference to its predecessor's output.

== Summary

TaskGraph provides 15+ infrastructure task types plus intelligent agentic task types:

* ✅ **Core** - ServiceTask, ScriptTask
* ✅ **HTTP/REST** - HttpTask, RestTask, GraphQLTask
* ✅ **Database** - SqlTask, NoSqlTask, BatchSqlTask
* ✅ **File** - FileTask, CsvTask, JsonTask, XmlTask
* ✅ **Messaging** - MessagingTask, KafkaTask, RabbitMQTask
* ✅ **Cloud** - S3Task, BlobStorageTask, LambdaTask
* ✅ **Utilities** - DelayTask, LogTask, TransformTask
* ✅ **Intelligent** - LlmTask (`llm.inference`), ControlTask (`control.policy`)
* ✅ **Human-in-loop (library)** - ManualTask (implemented in GCU with forms, notifications, escalation, timeout)
* ✅ **Office Documents** - XlsxTask, DocxTask, PptxTask with full Groovy DSL and Apache POI adapters (see <<tg-15>>)
* 🔶 **Planned** - `human.input` FlowTypeRegistry factory (wires ManualTask into flow graphs), `@EffectClass` annotation

All tasks inherit features from TaskBase:
* Retry logic
* Circuit breaker
* Timeout handling
* Idempotency
* Event emission
* Error handling

Intelligent task types additionally provide:
* `WorkingMemory` integration for cross-node state sharing
* LLM provider abstraction via injected `llmCallFn`
* Structured JSON output with corrective retry
* Real-time token streaming via `PipelineEventBus`
* Policy-driven conditional branching via `PolicyEvaluator`
* Human-in-the-loop via `ManualTask` (library) / `human.input` factory (planned)
