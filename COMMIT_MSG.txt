v2.1 concurrent correctness hardening: dataflow, promises, pool, gstream

=== ConcurrentPool (v1.2) ===
- scheduleListener() now calls pool.execute() so closed-state checks and
  admission control are respected when firing dataflow listeners
- DataflowPromise timeout()/orTimeout() now use sharedScheduledExecutor
  one-shot timers; no virtual thread parked for the timeout duration
- PromisePoolContext.defaultPool declared volatile (broken DCL corrected)
- DataflowExpression.listenerErrors capped at 100 via collectListenerError()

=== Dataflow (v2.1) ===
- DataflowVariable.get(timeout,unit) no longer binds TimeoutException as a
  permanent error on the DFV; timeout is caller-local, DFV stays PENDING
- All task() overloads now call pool.execute() so pool lifecycle/closed-state
  respected; pool closure bound as error on DFV
- scheduleListener() dispatches via pool.execute()
- listenerErrors queue capped at 100 entries
- Dead null-check removed from one-arg DataflowExpression constructor
- DataflowFactory.taskWithTimeout() uses pool.executeWithTimeout() with
  scheduled-executor timer; CancellationException/TimeoutException race
  maps to TimeoutException bound on the DFV

=== Promises (v1.1) ===
- onSuccess/onError/onComplete: eliminated double-invocation on already-
  completed promises (guaranteed exactly-once callback firing)
- fail() respects single-assignment: CAS(PENDING->FAILED) only; completed
  promise silently ignores further fail() calls
- timeout()/timeout(fallback)/orTimeout() use sharedScheduledExecutor
  one-shot timers instead of blocking virtual-thread sleep

=== Gstream (v2.1) ===
- distinctBy: HashSet -> ConcurrentHashMap.newKeySet() (parallel-safe)
- windowed: off-by-one/phantom-window fixed via firstCall bootstrap pattern
  (boundary cases size==count, size==1, size>count all now correct)
- onErrorContinue: 1000 consecutive-error guard prevents infinite loop;
  counter resets on success
- assert -> Objects.requireNonNull in tee/mapMulti/onErrorContinue/distinctBy
- NEW executeWith(ExecutorPool, Closure): run terminal op inside a
  ConcurrentPool instead of ForkJoinPool.commonPool()

=== Tests ===
- GstreamTest: 100 tests (up from ~70) covering all fixes + executeWith
- Full suite green: dataflow x2, promises, gstream
